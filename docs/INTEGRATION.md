# 커뮤니티·큐레이션 통합

통합 브랜치: `integration/community-curation`. 원격 push·main 병합·배포는 실행하지 않았다.

## 최신 원본

사용자가 전달한 `BUYORNOT.zip`의 2026-11-06 작업본을 적용했다. 이 ZIP은 GitHub의 이전 `feat/part-a-community` 브랜치보다 최신이며, 별도 홈·공통 상단바·PNG 로고·80개 상품 예시·공유·실제 상품 조회·로컬 파일 저장을 포함한다.

홈·공통 상단바·커뮤니티 CSS, 상품 시드 2개 파일, 상품 이미지 컴포넌트, 커뮤니티 작성폼, 로고 파일은 ZIP과 바이트 단위로 동일하다. 기존 프로젝트의 Supabase 설정·인증·큐레이션·마이페이지·가상 룸·로컬 계정 데이터는 보존했다. 패키지 버전은 같아 추가 의존성이 필요하지 않았다.

## 화면과 연결

| 주소             | 화면                       |
| ---------------- | -------------------------- |
| `/`              | ZIP 원본의 별도 홈         |
| `/community`     | ZIP 원본의 살말 커뮤니티   |
| `/creators/seoa` | 기존 큐레이션 룸과 추천 숍 |
| `/account`       | 공통 마이페이지            |
| `/login`         | 기존 공통 로그인           |

원본 홈의 큐레이션 준비 중 버튼은 실제 룸으로 연결한다. 원본 로고를 큐레이션·마이페이지·기존 로그인 화면에도 사용한다. 원본 상단바의 로그인된 계정 버튼은 My Page로 연결한다. 커뮤니티·마이페이지의 원글 링크는 `/community?post=...`를 사용한다.

커뮤니티는 기존 로컬 테스트 계정과 Supabase의 검증된 ID를 인식한다. ZIP의 개발용 1111 미리보기 로그인은 개발 환경에서만 유지한다. 기존 로컬 테스트 아이디도 원본 로그인 모달에서 사용할 수 있다. 가입 및 소셜 로그인 모달의 미연결 기능은 원본 상태이며, 기존 `/login`·`/signup`·카카오 로그인 경로는 유지된다.

## 데이터 보존

ZIP 원본의 `FileCommunityPersistence`에 따라 개발 환경에서 `.data/community.json`에 글·투표를 저장한다. 기존 임시 상품 6개가 저장돼 있으면 해당 구형 예시만 80개 원본 시드로 갱신하고 직접 작성한 글·투표는 보존한다. 세션은 파일에 저장하지 않는다.

큐레이션 테스트 활동·가상 룸은 기존 `.local-test-accounts/activity.json`을 유지한다. 환경 변수·비밀번호 해시·저장한 비공개 신체 정보·커뮤니티 실행 데이터는 Git에서 제외한다.

## 운영 범위

커뮤니티는 로컬 단일 서버의 파일 저장 방식이며 운영 DB·다중 서버·실시간 집계는 미연결이다. 원본 샘플 상품 가격은 조회 시점의 스냅샷이다. 커뮤니티 상품 조회기는 ZIP의 원본 DNS/IP 고정·리디렉션 검증·응답 제한 구현을 유지한다. 큐레이션 작성폼의 상황·신체 정보 UI와 커뮤니티 작성폼 공통화는 별도 작업이다.

## 검증

`npm run check`: 린트·타입·포맷·270개 테스트 통과. `npm run build` 통과. 홈과 `/community` HTTP 200 확인. 로컬 저장 데이터의 상품 80개 및 구형 플레이스홀더 0개 확인. 원본 제품·스타일·로고 파일 일치 확인. 실제 사용자 신체 정보 입력이나 게시·배포는 실행하지 않았다.
