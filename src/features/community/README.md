# Part A · 살말 커뮤니티

## 게시글 공유

공개 게시글 상세 창의 우측 상단에 공유 아이콘을 제공합니다. Web Share API를 지원하면 기기 공유 메뉴를 열고, 미지원·실패 시 `/community?post=<게시글 ID>` 링크를 복사합니다. 사용자 취소 시 복사하지 않으며 클립보드 접근 거부 시 직접 선택·복사 가능한 링크를 표시합니다. 공유 링크에는 작성자 신체 정보나 기존 필터 쿼리를 포함하지 않습니다.

공유 URL로 진입하면 기존 `getPost` 서버 액션의 권한 검사 후 상세 모달을 엽니다. 삭제되었거나 접근할 수 없는 글은 오류 안내를 표시합니다. 비공개 글에는 공유 버튼을 표시하지 않으며 공유 토큰이나 비공개 접근 권한은 새로 부여하지 않습니다. 상세 모달을 닫으면 `post` 쿼리만 제거합니다. 외부 공유 대상은 사용자가 기기 메뉴에서 선택합니다. 로컬 미리보기 URL은 다른 기기에서 접근할 수 없으며 실제 외부 공유는 배포 주소가 필요합니다.

## 80종 실제 상품 카드 (2026-11-06)

잡화 16개는 가방 8개·주얼리 4개(목걸이·반지·팔찌·귀걸이)·목도리 4개로 구성했습니다. 교체한 8개도 무신사 실제 상품 사진과 상세 링크를 사용하며, 각 품목에 맞는 고민 문구를 제공합니다. 다른 카테고리는 각각 16개, 전체 80개와 고유 닉네임을 유지합니다.

`seed.ts`와 `seed-products.ts`는 중복 없는 무신사 상품 80종을 사용합니다. 의류·뷰티·신발·잡화·명품 카테고리마다 16개이며 기존 30개에 뷰티 16개, 신발 8개, 잡화 10개, 명품 16개를 추가했습니다. 명품 카드는 무신사 부티크 상품을 사용합니다. 닉네임 80개도 모두 다르게 구성했습니다. 각 상품의 상세 페이지에서 공식 `image.msscdn.net` 사진 주소를 확인했으며, 상품 링크와 사진 경로의 상품 ID가 일치합니다. 원래 6종은 2026-10-22 가격을 유지하고 추가 74종은 이번에 읽은 상품 페이지의 가격 스냅샷을 사용합니다. 실시간 가격·재고 조회는 없습니다. 고민·닉네임·프로필·투표 수는 예시 데이터입니다.

테스트는 카드 80개와 카테고리별 16개, 닉네임·상품 URL·상품명·이미지의 중복 없음, 공식 이미지 호스트 및 상품 ID 일치를 확인합니다. 상품 정보는 `seed.ts`와 `seed-products.ts`의 각 상품 링크에서 확인할 수 있습니다. 개발 서버 메모리에 기존 카드가 남아 있다면 서버 재시작 후 반영됩니다.

## 현재 로그인 동작 (2026-10-27 후속 요청)

로그인 화면 확인용으로 아이디/이메일 `1111`, 비밀번호 `1111`을 입력하면 `loginPreview`가 개발 환경에서만 임시 세션을 발급합니다. 프로덕션에서는 발급과 조회를 모두 차단합니다. 실제 계정 인증이 아니며, 아래 미연동 기록 중 로그인 부분은 이 후속 요청으로 변경됐습니다.

입력값은 서버 액션으로 전달되며 비밀번호는 저장하지 않습니다. 무작위 세션 토큰을 HttpOnly/SameSite=Lax 쿠키 `buyornot-preview`에 저장합니다. 자동 로그인 선택 시 최대 하루, 미선택 시 브라우저 세션 쿠키를 사용합니다. 서버 메모리 세션은 하루 만료되며 재시작 시 초기화됩니다. 로그아웃 시 쿠키와 세션을 삭제합니다. 이전 데모 쿠키는 인증에 사용하지 않습니다.

이메일 가입·계정 찾기·비밀번호 재설정·소셜 로그인은 미연동입니다. 환경 변수나 의존성 변경은 없습니다. `npm run check`에서 30개 테스트가 통과했습니다. 임시 로그인 성공/실패, 투표, 로그아웃, 이전 쿠키 거부, 프로덕션 차단을 포함합니다.

브랜치: `feat/part-a-community`. 담당 이슈 번호는 아직 전달되지 않았습니다.
수정 범위: `src/features/community/`, 승인받은 `src/app/page.tsx` 및 `src/app/layout.tsx`. 의존성·공통 스타일·파트 B 변경 없음.

## Mock 인터페이스

`actions.ts`: `loadCommunity`, `getPost`, `savePost(input, id?)`, `deletePost`, `votePost`, `getProductInfo`, `logoutDemo`.
각 응답은 `Result<T>` (`{ok:true,data:T}` 또는 `{ok:false,error:string}`)입니다.
타입은 `types.ts`. 로그인 사용자는 클라이언트 인자가 아니라 서버 쿠키의 무작위 세션으로 판별합니다.
`store.ts`는 프로세스 메모리에만 저장합니다. 재시작·서버리스 인스턴스 간 영속성을 보장하지 않습니다.
데모 세션 발급 액션과 체험 버튼은 제거했습니다. 기존 데모 쿠키는 인증에 사용하지 않습니다. 실제 인증 제공자 결정 및 연결 전에는 모든 요청이 비회원으로 처리됩니다. 아래 데모 로그인 검증 기록은 제거 이전의 이력입니다.

`product.ts`는 허용 쇼핑몰 URL을 검증·정규화합니다. `product-fetch.ts`가 서버에서 실제 상품 페이지를 조회하고, `product-metadata.ts`가 JSON-LD Product 및 Open Graph에서 상품명·브랜드·가격·공식 이미지를 추출합니다. `product-loader.ts`는 결과를 5분간 캐시합니다(최대 200개). 추가 환경 변수·외부 API·의존성은 없습니다.
상품 정보를 확인하지 못하면 가짜 이름·가격으로 대체하지 않고 재시도 가능한 오류를 표시합니다. 쇼핑몰의 접근 차단이나 메타데이터 부재 때문에 모든 URL의 성공을 보장하지는 않습니다. 불러오기가 완료되어야 등록할 수 있으며, 저장 시에도 서버에서 상품 정보를 확인하고 스냅샷을 저장합니다. `store.save`의 네 번째 내부 인자로 검증한 `Product`를 전달하며 공개 Server Action 계약은 유지합니다.
`product-preview.tsx`는 실제 사진·상품명·브랜드·원화 가격·상품 링크를 보여줍니다. 사진 실패 시 다시 불러오기 버튼을 제공합니다. 기존 도메인 기반 플레이스홀더와 “실제 상품명·가격은 쇼핑몰에서 확인해 주세요.” 문구는 제거했습니다.
샘플 피드는 5개 카테고리별 16개 상품의 링크·공식 상품 이미지·가격 스냅샷을 사용합니다. 고민 글과 투표는 데모 데이터입니다.

`clipboard-modal.tsx`가 로컬 클립보드 모듈이며 공용 `/lib/clipboard`는 추가하지 않았습니다.

## DB 연결 계약

실제 DB와 마이그레이션은 추가하거나 실행하지 않았습니다. 공유 스키마 조율 후 다음 계약으로 연결합니다.

- `posts`: UUID PK, author_id FK, product_url/domain/name/brand/image, price_amount, currency, category CHECK, concern_text CHECK 1~300, visibility CHECK, body_profile_snapshot JSONB, created_at/updated_at/deleted_at, share_token_hash.
- `votes`: UUID PK, post_id FK, user_id FK, choice CHECK BUY/NOT, UNIQUE(post_id,user_id), created_at/updated_at.
- `profiles`: user_id PK, nickname 및 기획의 프로필 필드. OAuth의 사용자 ID와 매핑.
- RLS: 공개·미삭제 또는 본인 게시글만 읽기, 작성/수정/삭제는 auth.uid() 검증, 투표는 접근 가능한 글과 현재 사용자만 허용.
- 집계는 DB 트랜잭션/RPC로 처리. 리얼타임 구독은 권한 필터 후 적용.
- FOLLOWERS는 팔로우 관계, LINK_ONLY는 만료/회수 가능한 해시 토큰 검증 후 열람. 현재 Mock에서는 본인만 조회하도록 제한.

`store.ts`의 `// TODO: connect to lib/supabase` 지점에서 교체합니다.
현재 필요한 환경 변수는 없습니다. 추후 Supabase 도입 시 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`가 필요하며 인증 방식·키 계약부터 조율합니다. 서버 권한 키는 클라이언트로 전달하지 않습니다.
상품 수집기는 DNS 결과의 모든 IP를 검증하고 연결 IP를 고정합니다. 각 리다이렉트에서 URL·DNS를 재검증하며, 전체 10초·응답 2MiB·리다이렉트 5회 제한을 적용합니다. 사설 IP와 허용 목록 밖의 호스트는 차단합니다.
